📱 PROBLÈME IDENTIFIÉ
═══════════════════════════════════════════════════════════════════════════

SYMPTÔME:
   Sur iOS/iPad, lors de la première demande de permission de localisation,
   l'application ouvre IMMÉDIATEMENT les paramètres système sans afficher
   la popup de demande de permission native.

IMPACT:
   ❌ Mauvaise expérience utilisateur
   ❌ Rejet par Apple (non-conformité aux guidelines)
   ❌ Impossible d'accorder la permission directement

═══════════════════════════════════════════════════════════════════════════

🔍 CAUSE DU BUG
═══════════════════════════════════════════════════════════════════════════

FICHIER: /lib/custom_code/actions/check_and_request_permission.dart
LIGNES: 51-54 (AVANT CORRECTION)

CODE DÉFAILLANT:
   ❌ if (status.isPermanentlyDenied || status.isRestricted) {
   ❌     await openAppSettings();  // ← Ouvre AVANT de demander
   ❌     return 'permanently_denied';
   ❌ }

PROBLÈME:
   Le code vérifie isPermanentlyDenied/isRestricted AVANT de demander
   la permission à l'utilisateur. Sur iOS/iPad, le statut peut être
   'restricted' dès le début, ce qui ouvre les paramètres immédiatement
   sans jamais afficher la popup système.

SÉQUENCE INCORRECTE:
   1. App démarre
   2. Vérifie status → denied/restricted
   3. ❌ Ouvre les paramètres IMMÉDIATEMENT
   4. ❌ Popup système jamais affichée
   5. ❌ Utilisateur confus

═══════════════════════════════════════════════════════════════════════════

✅ SOLUTION IMPLÉMENTÉE
═══════════════════════════════════════════════════════════════════════════

NOUVELLE LOGIQUE (CONFORME APPLE GUIDELINES):

   // Étape a : Vérifier si déjà accordée
   if (status.isGranted || status.isLimited) {
       return 'granted';
   }

   // Étape b : Si denied, DEMANDER la permission
   if (status.isDenied) {
       // Étape c : Déclencher la popup système
       var newStatus = await permission.request();

       // Étape d : Ré-évaluer après réponse utilisateur
       if (newStatus.isGranted || newStatus.isLimited) {
           return 'granted';
       } else if (newStatus.isPermanentlyDenied) {
           // Étape e : SEULEMENT maintenant, ouvrir les paramètres
           await openAppSettings();
           return 'permanently_denied';
       } else {
           return 'denied';
       }
   }

   // Si déjà permanentlyDenied (refus antérieur)
   if (status.isPermanentlyDenied || status.isRestricted) {
       await openAppSettings();
       return 'permanently_denied';
   }

SÉQUENCE CORRECTE:
   1. App démarre
   2. Vérifie status → denied
   3. ✅ Demande la permission (popup système)
   4. ✅ Utilisateur répond (Autoriser/Refuser)
   5. ✅ Ré-évalue le statut
   6. ✅ Si refusé définitivement → ALORS ouvre paramètres
   7. ✅ Conforme Apple Guidelines

═══════════════════════════════════════════════════════════════════════════

📊 COMPARAISON AVANT/APRÈS
═══════════════════════════════════════════════════════════════════════════

AVANT (❌ INCORRECT):
   Status: denied → Vérifie permanentlyDenied → Ouvre paramètres
   
   Résultat: Popup jamais affichée, paramètres ouverts immédiatement

APRÈS (✅ CORRECT):
   Status: denied → Demande permission → Popup affichée → 
   Utilisateur répond → Ré-évalue → Si besoin, ouvre paramètres
   
   Résultat: UX fluide, conforme Apple, popup affichée

🎯 CAS D'USAGE COUVERTS
═══════════════════════════════════════════════════════════════════════════

✅ CAS 1: Première demande
   Status: denied → Demande → Popup → Autoriser → granted

✅ CAS 2: Refus unique
   Status: denied → Demande → Popup → Refuser → denied (peut redemander)

✅ CAS 3: Refus définitif
   Status: denied → Demande → Popup → Refuser + "Ne plus demander" →
   permanentlyDenied → Ouvre paramètres

✅ CAS 4: Déjà refusé définitivement
   Status: permanentlyDenied → Ouvre paramètres directement

✅ CAS 5: Restrictions parentales (iPad)
   Status: restricted → Ouvre paramètres (pour info)
